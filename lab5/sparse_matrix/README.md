# 稀疏矩阵：工程代码与原理讲解

对应题目：https://oj.qd.sdu.edu.cn/v2/problemSet/243/problem/0/0

本项目使用 C++14。矩阵使用行主序的一维三元组数组；加法、乘法、转置都直接在稀疏结构上进行，没有把矩阵转换为二维数组。所有矩阵元素均用 `int` 存储，计算按题目要求模拟 32 位整数回绕。

## 2. 先理解题目的状态规则

始终只有一个当前矩阵 `P`。操作 `1` 重置 `P`，操作 `4` 输出尺寸及全部元素，操作 `5` 令 `P=P^T`，不输出内容。

操作 `2`、`3` 都先完整读入另一个矩阵 `Q`：

| 操作 | 合法条件 | 合法时 | 不合法时 |
|---|---|---|---|
| 乘法 `2` | `P.columns == Q.rows` | `P = P * Q` | `P = Q`，输出 `-1` |
| 加法 `3` | 行数相同且列数相同 | `P = P + Q` | `P = Q`，输出 `-1` |

特别注意：不合法时不能保留旧的 `P`，也不能因为提前发现维度不匹配就跳过 `Q` 的输入，否则后续操作会被错误解析。

## 3. 为什么需要稀疏矩阵

一个 `n×m` 的普通矩阵需要存储 `n*m` 个值。如果绝大多数元素都是零，存储这些零会浪费空间，遍历它们也会浪费计算。

设非零元素个数为 `t`，密度可写为 `t/(n*m)`。稀疏矩阵只存储有信息的非零位置，其余位置通过“不存在对应记录”隐式表示为零。

例如：

```text
A = [0  5  0   0]
    [0  0  0  -2]
    [7  0  0   0]
```

它有 12 个位置，却只有 3 个非零项。使用从 0 开始的内部坐标，只需保存：

```text
(0, 1,  5)
(1, 3, -2)
(2, 0,  7)
```

还必须单独保存行数 `3`、列数 `4`。原因是三元组不能完整反映尾部的全零行、全零列；全零矩阵更是没有任何三元组。

若 `int` 占 4 字节，一个普通三元组通常占 12 字节，因此理想有效载荷约为 `12*t`，而稠密存储是 `4*n*m`。只有足够稀疏时三元组才更省空间；实际还需要计入 vector 的容量、对象元数据和算法工作区。不能简单认为稀疏结构在任何密度下都更省内存。

## 4. 三元组与行主序

三元组 `(row, column, value)` 分别记录行、列和值。

“行主序”指先比较行号，行号相同时再比较列号：

```text
(0,1) < (0,3) < (2,0) < (2,4)
```

源码使用 `vector<MatrixTerm>`。vector 的有效元素连续存放，因此它就是可自动管理容量的一维三元组数组。

类始终维持三个关键条件：

1. 只存非零项。
2. 同一个坐标只有一项。
3. 坐标按行主序严格递增。

这三个条件使加法可以归并、同一行的元素可以连续扫描、输出可以只使用一个游标。它们是算法能够正确衔接的基础。加法相消得到零、乘法累加得到零，都必须丢弃该项。

输入的坐标从 1 开始，类内部从 0 开始。转换只在读取三元组时进行，避免不同算法反复混用两种下标。

## 5. 建立矩阵：输入稠密不等于稠密存储

重置操作要求读入全部元素，这是输入协议决定的，无法跳过零的输入。

代码依次读一个 `value`：若为零就忽略，非零就追加 `(row,column,value)`。整个过程只有当前输入值和非零数组，不建立 `int matrix[n][m]`，也不建立 `vector<vector<int>>`。

建立耗时 `O(n*m)`，最终有效存储为 `O(t)`。非零项天然按行主序到达，不需要额外排序。

## 6. 加法：两个有序序列的归并

数学公式为 `C(i,j)=A(i,j)+B(i,j)`，但不需要访问每一个位置。

令 `i`、`j` 分别指向两个非零数组的当前项：

1. 若 A 当前坐标较小，B 在这个坐标上就是零，直接复制 A 当前项。
2. 若 B 当前坐标较小，同理复制 B 当前项。
3. 若坐标相同，累加两项；结果非零才保存，同时移动两个指针。
4. 一方用尽后，另一方剩余项直接追加。

例如：

```text
A: (0,1,5),  (1,3,-2), (2,0,7)
B: (0,1,-5), (1,0,4),  (2,2,6)
C:             (1,0,4), (1,3,-2), (2,0,7), (2,2,6)
```

`(0,1)` 处的 `5+(-5)=0` 被删除。两个指针只向前移动，每项最多处理一次，因此时间为 `O(tA+tB)`，不依赖矩阵全部位置数。

## 7. 乘法：只展开有贡献的非零项

若 A 为 `n×k`，B 为 `k×m`，则结果 C 为 `n×m`：

```text
C(i,j) = Σ A(i,p) * B(p,j)，p=0..k-1
```

普通三重循环会遍历许多零。稀疏乘法利用：任一因子为零，乘积就是零。

因此，对于 A 的非零项 `A(i,p)`，只需要访问 B 的第 p 行的非零项 `B(p,j)`，把乘积累加到 `C(i,j)`。

### 7.1 行边界数组

B 已经按行排序，属于同一行的三元组连续存储。辅助数组 `start` 指出每一行在一维非零数组中的范围：

```text
B 第 p 行 = terms[start[p] ... start[p+1]-1]
```

例如各行非零项数为 `[2,0,3]` 时：

```text
start = [0,2,2,5]
第 0 行：下标 [0,2)
第 1 行：下标 [2,2)，空行
第 2 行：下标 [2,5)
```

末尾多放一个边界能统一处理最后一行。注意 `start` 保存的是三元组数组的位置，不是矩阵元素值。这里借用了 CSR（压缩稀疏行）的行索引思想，矩阵本体仍然是题目要求的三元组数组。

### 7.2 一行累加器

计算结果第 i 行时使用三个一维工作数组：

- `sums[j]`：当前结果行第 j 列的部分和。
- `mark[j]`：这个位置最近被哪一个结果行使用。
- `touched`：当前行实际访问到的列号。

首次访问本行的第 j 列时，把 `sums[j]` 清零，记录 `mark[j]=i`，并把 j 加入 `touched`；再次访问该列时直接累加。

举例：

```text
A 的某一行是 [0,2,0,3]
B 的第 1 行是 [5,0,7]
B 的第 3 行是 [0,4,1]
结果这一行 = 2*[5,0,7] + 3*[0,4,1] = [10,12,17]
```

A 的其他两个位置是零，对应的 B 行完全无需访问。

标记数组让代码不必为每个结果行清空全部 m 个累加位置。行与行之间复用同一份工作区，额外空间是 `O(m)`，没有存储 `n*m` 个结果位置。

最后将 `touched` 排序，按列号递增保存非零结果。这一步必要：按 A 的列依次展开 B 的行，触及结果列的先后顺序不一定递增。相同列只会被记录一次，因为有 `mark` 去重。

### 7.3 乘法复杂度

令 `F = Σ_(i,p)属于A非零项 nnz(B第p行)`，即实际访问的非零乘积数；令 `d_i` 是结果第 i 行触及的不同列数。这里 `d_i` 也包括最终相消为零的列。

本实现的时间为：

```text
O(B.rows + B.columns + tA + tB + F + Σ d_i log(d_i+1))
```

其中包括行边界构造、工作区初始化、实际非零乘积和触及列的排序。除输入与结果三元组外，额外空间为 `O(B.rows+B.columns)`。

它的计算量随非零结构变化，不能笼统地说成 `O(tA+tB)`。极端情况下稀疏矩阵相乘也可能得到稠密结果，必须为实际产生的非零项付出存储成本。

## 8. 快速转置：计数、前缀和、稳定散布

转置的数学定义为 `A^T(j,i)=A(i,j)`，尺寸从 `n×m` 变为 `m×n`。

单独交换每个三元组的行列是不够的，因为交换后的数组可能不再按行主序排列。可以交换后排序，耗时 `O(t log t)`；本实现采用快速转置。

1. 统计原矩阵各列的非零项数。原第 c 列将成为转置矩阵的第 c 行。
2. 计算排他前缀和，得到每个目标行在结果数组中的起始位置。
3. 顺序扫描原数组，把 `(r,c,v)` 放入目标第 c 行的下一个位置，并更新该位置。

对前面的 A，各原列计数为 `[1,1,0,1]`，对应目标行起点为 `[0,1,2,2]`。转置后按顺序存储：

```text
(0,2,7), (1,0,5), (3,1,-2)
```

为什么不需要再排序？不同目标行已经由前缀和分配到各自连续区间；对于同一个原列，原数组中的原行号递增，变成新列号后仍递增。因此结果天然满足行主序。

时间为 `O(m+t)`，额外工作区为 `O(m)`，另需 `O(t)` 存储结果。全零矩阵直接交换尺寸即可。

## 9. 按普通矩阵输出

输出协议要求打印全部 `n*m` 个位置，所以此操作需要 `O(n*m)` 时间，这是输出量本身决定的。

代码同时维护矩阵坐标 `(row,column)` 和三元组游标 `pos`。当前位置与 `terms[pos]` 一致就输出其值并前移游标，否则输出零。

整个过程直接写输出流，不会先创建完整二维矩阵。辅助空间为 `O(1)`，不计标准流自身的缓冲区。

## 10. int 自然溢出为什么要专门处理

本题要求把所有计算视为 `int` 自然回绕。在 32 位环境中，这对应模 `2^32` 的计算，再把结果解释为 `[-2^31,2^31-1]` 内的有符号值：

```text
2147483647 + 1 -> -2147483648
65536 * 65536 -> 0
-2147483648 * (-1) -> -2147483648
```

但是 C++14 中直接让有符号 `int` 溢出属于未定义行为，编译器优化时不必保留预期的回绕结果。仅仅说“我的机器上能回绕”并不足以保证正确。

代码先把两个 int 转为 32 位 `unsigned int`，使用标准规定的模运算，再通过范围内的 int 运算映射回有符号值。它没有依赖越界的 unsigned-to-int 转换，也没有依赖 `long long` 累加后一定不会溢出的假设。

对每次乘法和每次累加分别取模，与数学上的精确乘加最后统一取模一致，因为模运算满足加法、乘法的封闭关系。出现回绕为零时，该项同样不应存入稀疏结构。

## 11. 工程设计与验收重点

- 数据封装：外部无法直接修改三元组数组，防止破坏有序性或引入重复坐标。
- 职责分离：矩阵类提供数学操作，主程序处理题目的状态迁移。
- 不修改输入：加法、乘法、转置返回新对象；计算完成后再赋给当前矩阵。
- 自动资源管理：vector 管理内存，使用编译器生成的复制/移动操作，无需手写析构和裸指针管理。
- 不合法维度：主程序执行题目指定的 `P=Q` 与 `-1` 输出，类本身则通过异常报告误用。
- 正确输出：没有交互提示、调试打印或额外标签；每行数字之间只有空格。

本地验证包括网页的三组公开样例、固定随机种子的 25001 次操作对拍，以及 1200×1200 对角矩阵连续 200 次乘法。随机参考程序独立使用 Python 精确整数计算并取模，覆盖维度不匹配后的替换、全零/零尺寸矩阵、相消、负数、整数边界和连续转置。用于对拍的二维参考矩阵仅存在于测试脚本中，不属于提交程序。

## 12. 复杂度速查

设矩阵尺寸为 `n×m`，非零项数为 `t`。

| 操作 | 时间 | 不计输入和结果的额外空间 |
|---|---|---|
| 稠密输入并压缩 | `O(n*m)` | `O(1)` |
| 已排序三元组输入 | `O(t)` | `O(1)` |
| 加法 | `O(tA+tB)` | `O(1)` |
| 乘法 | 见第 7.3 节 | `O(B.rows+B.columns)` |
| 快速转置 | `O(m+t)` | `O(m)` |
| 阵列形式输出 | `O(n*m)` | `O(1)` |

上表使用题目通常的正尺寸情形；代码也支持零尺寸，输出含 n 个行结束符时仍需要相应的输出时间。vector 的扩容使追加复杂度为均摊界。
